# Write and revise together

The editor presents the proposal as one continuous document with a section outline and team guidance. Model-generated text is editable; the latest human-saved version is the publishing source.

## Open the draft

Open a saved grant and choose **Grant editor**. If initial drafting completed, the outline contains sponsor-aware section headings and the document contains generated starting text.

  <figcaption>Use the outline to navigate, the center document to edit, and the right panel to guide the team or request a rewrite.</figcaption>

## Organize sections

Use the left outline to:

- select and scroll to a section;
- rename its heading and description;
- add a section required by the sponsor;
- move sections into the desired publishing order.

Section order is persisted with the shared grant and used by publishing.

## Edit and save

Edit proposal language directly in the document. Choose **Save document** to create a new immutable version attributed to the signed-in user.

Human edits have the last word. A generated rewrite never needs to be accepted, and publishing uses the saved document state rather than an unseen model conversation.

## Guide a rewrite

Add guidance to the current section:

- **Comment** records a shared note without forcing a rewrite.
- **Question** asks for missing information or evidence.
- **Rule** states a constraint the next draft must follow.

Questions and rules can launch research and rewrite the affected section. Review the result, correct it directly, and save only the version you want the team to use.

<div class="callout warning"><strong>Do not treat generation as evidence.</strong> Verify quantitative claims, citations, eligibility statements, and sponsor requirements against their linked source before approval.</div>

## Work with versions

The version selector identifies the author and saved version. Load an older version to inspect it; restoring creates a new head version and does not delete intervening history.

Use version history when:

- a rewrite weakens an important clinical distinction;
- two contributors make competing edits;
- sponsor guidance changes;
- the team needs to document who approved what.

## Refresh shared work

Your save appears locally as soon as it succeeds. Choose **Refresh shared changes** to pull teammate updates. If the application detects that your base version is stale, reconcile the newer version before saving again.
